## 1. 비교할 정렬

| 구분 | 정렬 | 고른 이유 |
| --- | --- | --- |
| 배운 것 ① | 퀵 정렬 | 평균적으로 가장 빠르다고 배웠다. 제자리 정렬이고 불안정하다 |
| 배운 것 ② | 병합 정렬 | 최악에도 `O(n log n)`이고 안정 정렬이다. 대신 보조 배열이 필요하다 |
| 배우지 않은 것 | 콤 정렬 (Comb sort) | 버블 정렬을 조금 고쳐서 `n log n`에 가깝게 만든 정렬이다. 코드가 짧다 |

세 정렬의 장점이 서로 다르게 나오도록 골랐다. 퀵은 속도와 제자리, 병합은 안정성과 최악 보장, 콤은 단순함이다. 그래서 "무엇이 제일 빠른가"보다 "무엇을 주고 무엇을 얻는가"를 볼 수 있다고 생각했다.

## 2. 코드 구성

세 정렬을 같은 원소 타입과 같은 측정 방법으로 돌려야 공정하게 비교할 수 있다. 원소는 `Rec {key, tag}`로 했다. `key`로 정렬하고 `tag`에는 입력 순서를 저장한다. 정렬 후에 같은 key끼리 tag가 오름차순이면 안정 정렬이다. `int` 배열은 `3`과 `3`을 구별할 수 없어서 안정성을 확인할 수 없다.

| 파일 | 역할 |
| --- | --- |
| `src/sort.h` | `Rec`, 측정 구조체 `Stats`, 비교·교환 매크로 `LT` `SWAP` |
| `src/quickSort.c` · `mergeSort.c` · `combSort.c` | 정렬 구현 |
| `src/main.c` | 입력 생성, 시간·비교·이동 측정, 정렬 여부와 안정성 검사, 표/CSV 출력 |
| `tests/test_sort.c` | 크기 0~300, 입력 4종을 `qsort` 결과와 비교 (4,816개 검사, 실패 0) |
| `tools/plot.py` | CSV로 그래프 그리기 (matplotlib) |

측정 방법은 다음과 같다.

- 비교·이동 횟수는 정렬 안에서 직접 센다. 입력을 고정 씨앗으로 만들어서 언제 돌려도 같은 값이 나온다. 교환 1회는 이동 3회, 병합의 복사는 1회로 셌다.
- 시간은 `clock_gettime`으로 재고 입력 복사는 뺐다. 5회 평균이다. 기계 상태에 따라 달라지므로 같은 표 안에서만 비교한다.
- 추가 메모리는 입력 배열 밖에 잡은 바이트, 재귀 깊이는 실제 최대 깊이다.
- 입력은 무작위, 정렬됨, 역순, 중복많음(key 0~15) 4종이다. 크기 변화 실험은 무작위 입력으로 `n = 1,000 ~ 64,000`까지 했다.

## 3. 알고리즘 설명

### 3.1 퀵 정렬 (배운 것)

가운데 원소를 pivot으로 잡고 작은 것은 왼쪽, 큰 것은 오른쪽으로 나눈 뒤 양쪽을 재귀로 정렬한다. Hoare 분할을 썼다. 작은 쪽만 재귀하고 큰 쪽은 반복문으로 처리해서 재귀 깊이를 `O(log n)`으로 줄였다. pivot을 맨 끝 원소로 잡으면 정렬된 입력에서 깊이가 `n`이 되어 스택이 넘칠 수 있기 때문이다.

- 시간: 평균 `O(n log n)`, 최악 `O(n²)` / 추가 메모리 `O(log n)`(스택) / 불안정 (멀리 있는 원소를 교환해서 같은 값의 순서가 바뀔 수 있다)

### 3.2 병합 정렬 (배운 것)

배열을 반으로 나눠 각각 정렬하고, 정렬된 두 구간을 앞에서부터 비교하며 합친다. 같은 값이면 왼쪽을 먼저 꺼내므로(`if (a[j] < a[i])`의 `<`) 안정 정렬이 된다. 합친 결과를 둘 곳이 필요해서 보조 배열 `n`칸을 쓴다.

- 시간: 항상 `O(n log n)` / 추가 메모리 `O(n)` / 안정

### 3.3 콤 정렬 (배우지 않은 것 — AI로 학습)

이 절은 Claude(AI)에게 콤 정렬을 물어보고 학습한 내용을 정리한 것이다. 질문과 답의 요약은 6절에 붙였다.

**배경.** 1980년 Dobosiewicz와 Borowy가 처음 설계했고, 1991년 Lacey와 Box가 다시 발견해서 "Combsort"라는 이름을 붙였다. 이름은 빗살처럼 벌어진 간격으로 원소를 비교하는 모양에서 왔다. Wikipedia는 콤 정렬이 버블 정렬을 개선한 방식이 Shellsort가 삽입 정렬을 개선한 방식과 같다고 설명한다. 멀리 있는 원소가 교환 한 번에 여러 칸을 움직이게 하는 것이다.

**버블 정렬의 문제.** 버블 정렬은 이웃한 원소끼리만 교환한다. 큰 값은 한 바퀴에 끝까지 가지만, 배열 끝쪽에 있는 작은 값은 한 바퀴에 한 칸씩만 앞으로 온다. 이런 작은 값을 거북이라고 부른다. 거북이 하나를 앞으로 보내는 데 `n`바퀴가 들고, 이것 때문에 `O(n²)`이 된다.

**아이디어.** 비교하는 두 원소의 간격(gap)을 처음에는 크게 잡아서 거북이를 한 번에 멀리 옮긴다. 그리고 바퀴마다 간격을 1.3으로 나눠 줄인다. 간격이 1이 되면 버블 정렬과 같아지는데, 이때는 이미 거의 정렬되어 있어서 금방 끝난다. 줄임 비율은 Dobosiewicz가 4/3을 제안했고, Lacey와 Box가 길이 약 1,000인 무작위 배열 20만 개 이상으로 실험해서 1.3이 좋다고 찾았다. 비율이 너무 작으면 비교가 쓸데없이 늘고, 너무 크면 거북이를 못 잡아서 간격 1에서 바퀴가 많이 든다. 간격이 9나 10이 되면 11로 바꾸는 규칙(rule of 11)도 이 실험에서 나온 보정으로 알려져 있다.

```c
void combSort(Rec *a, int n) {
    int gap = n, swapped = 1;
    while (gap > 1 || swapped) {
        gap = gap * 10 / 13;                    /* 1.3으로 나눔 */
        if (gap == 9 || gap == 10) gap = 11;    /* rule of 11 */
        if (gap < 1) gap = 1;
        swapped = 0;
        for (int i = 0; i + gap < n; i++)
            if (LT(a[i + gap], a[i])) { SWAP(a[i], a[i + gap]); swapped = 1; }
    }
}
```

**손으로 따라가 보기** (`n = 8`, 배열 `8 4 1 5 9 2 7 3`)

| 바퀴 | gap | 교환한 쌍 | 결과 |
| --- | --- | --- | --- |
| 1 | 6 | (8,7) (4,3) | 7 3 1 5 9 2 8 4 |
| 2 | 4 | (3,2) (5,4) | 7 2 1 4 9 3 8 5 |
| 3 | 3 | (7,4) (9,5) | 4 2 1 7 5 3 8 9 |
| 4 | 2 | (4,1) (7,3) | 1 2 4 3 5 7 8 9 |
| 5 | 1 | (4,3) | 1 2 3 4 5 7 8 9 |
| 6 | 1 | 없음, 종료 | 1 2 3 4 5 7 8 9 |

맨 뒤에 있던 작은 값 `3`이 첫 바퀴에서 6칸을 뛰어 앞쪽으로 갔다((4,3) 교환). 버블 정렬이면 한 바퀴에 한 칸씩만 움직인다.

**복잡도 (Wikipedia와 대조).** 최선 `Θ(n log n)`, 평균은 간격 단계 수를 `p`라 할 때 `Ω(n²/2^p)`, 최악 `O(n²)`, 추가 메모리 `O(1)`이다. 평균이 `n log n`이라고 증명된 것은 아니고 실험에서 `n log n`에 가깝게 나온다고 알려져 있어서, 4절에서 직접 재어 확인했다. 안정성은 자료마다 다르게 적혀 있어서(안정이라고 적은 글도 있다) 직접 쟀고, 결과는 불안정이었다. 멀리 있는 원소를 교환하기 때문이다.

**결과 정리**

1. 무작위 입력에서는 시간이 세 정렬 모두 약 1.9ms로 거의 같았다. 그런데 세부 숫자는 달랐다. 병합은 비교가 가장 적고(26만), 퀵은 이동이 가장 적고(21만), 콤은 비교가 퀵의 1.7배(67만)였다. 콤은 비교가 많은데도 시간이 비슷했다. 반복문이 단순하고 메모리를 앞에서부터 차례로 읽기 때문일 것 같지만, 캐시를 측정하지 않아서 확인하지는 못했다.
2. 병합은 입력에 상관없이 이동이 574,464로 같았다. 이미 정렬된 입력에서도 배열 전체를 복사하기 때문이다. 정렬됨·역순에서 병합이 퀵보다 느린 것(0.43~0.65ms 대 0.23ms)이 이 때문이다.
3. 퀵은 가운데 pivot을 써서 정렬됨·역순에서도 빨랐다. 맨 끝을 pivot으로 잡았으면 이 두 입력이 `O(n²)` 최악이었을 것이다. 다만 pivot이 계속 나쁘게 뽑히는 입력을 만들 수는 있어서 `O(n²)` 가능성은 남아 있다.
4. 콤 정렬은 이미 정렬된 입력에서도 비교를 61만 번 했다. 이동은 0이지만 간격이 1이 될 때까지 모든 간격 단계를 한 바퀴씩 돌아야 하기 때문이다. 버블 정렬이 정렬된 입력에서 `n-1`번 비교로 끝나는 것과 다르다.
5. 안정성은 예상대로 나왔다. 병합만 안정이고 퀵과 콤은 key가 같은 원소의 순서가 바뀌었다.

## 5. 결론과 한계

- 속도는 퀵이 가장 빨랐고 병합과 콤은 비슷했다. 무작위 입력에서 차이는 크지 않았다(64,000개에서 최대 1.3배). 콤 정렬이 10줄짜리 코드로 `n log n`에 가까운 성능을 낸 것이 가장 흥미로웠다. 버블 정렬에 간격 하나를 더한 것만으로 이만큼 좋아진다.
- 안정성이 필요하면 병합, 메모리가 부족하면 퀵이나 콤, 빨리 구현해야 하면 콤이 맞다고 생각한다.
- 한계는 다음과 같다. (1) 시간은 한 기계에서 5회 평균이라 실행마다 조금 달라진다. 그래서 항상 같은 비교·이동 횟수를 같이 적었다. (2) 콤 정렬의 최악 `O(n²)` 입력은 만들어서 재보지 않았다. (3) 퀵의 pivot은 가운데 원소 하나라서 나쁜 입력은 다루지 않았다. (4) 버블 정렬과 직접 비교하지 않아서 "콤이 버블보다 얼마나 빠른가"는 이론 설명에 그쳤다.
